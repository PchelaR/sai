# sai

Утилита для запуска ИИ-агентов (Claude Code и Codex) на VPS. Агент работает в изолированном Docker-контейнере, а папки проекта синхронизируются между локальным пк и VPS.

## Как это работает

- `sai setup` один раз настраивает чистую Ubuntu-VPS: создаёт пользователя `sai`, оставляет вход только по ключу на порту 28522, включает фаервол и fail2ban, ставит Docker и собирает базовый образ с Python (pyenv: 3.7, 3.11 и последняя 3.x) и Rust. Там же есть `uv`. Образ самого агента собирается за пару минут при первом `chat` с ним.
- Проект — это имя и одна или несколько папок, например фронтенд и бэкенд. `sai attach` добавляет папку к проекту, агент видит каждую папку как `/workspace/<папка>` и может менять все сразу.
- `sai chat` синхронизирует папки с VPS через mutagen и открывает агента. Агент видит только папки своего проекта и интернет, до самой VPS и других проектов доступа нет.
- Агент продолжает работать, даже если закрыть терминал. Повторный `sai chat` возвращает в ту же сессию.
- Секреты (`.env`, ключи, сертификаты и т.п.) и `.git` на VPS не попадают. Зависимости и результаты сборки тоже не синхронизируются ни в одну сторону: `node_modules`, `.venv` и `venv`, `target`, кэши Python, Next.js, Gradle, Flutter и т.п. (полный список в `src/ignores.rs`). Агент ставит зависимости на VPS сам.
- Перед каждым `chat` и каждые 3 минуты, если что-то изменилось, на VPS делается снапшот проекта. Хранятся все снапшоты за последний час, по одному в час за сутки и по одному в день за неделю. В списке снапшотов видно, что изменилось («deleted 3, changed 12»), так что легко найти момент до неудачной правки и откатиться к нему.
- Агентам запрещено удалять файлы и делать `git commit`/`git push`. Это проверяет сама программа агента по правилам, которые агент не может изменить. Запрет ловит команды вроде `rm`, но не удаление из кода (например, через Python), поэтому главная защита от потери файлов — снапшоты. `git push` невозможен в принципе: на VPS нет ключей.

## Требования

- OpenSSH, `curl` и `tar` (на macOS, Linux и Windows 10+ они уже есть). Mutagen для синка sai скачивает и ставит сам
- ssh-ключ, например `~/.ssh/id_ed25519`
- чистая VPS с Ubuntu 22.04 или новее и пароль от пользователя


## Установка

Скачайте архив под свою систему во вкладке Releases, распакуйте и положите `sai` в `/usr/local/bin`.

Дальше sai обновляется сам командой `sai upgrade` или клавишей `U` в меню. Раз в сутки sai проверяет, вышла ли новая версия, и пишет об этом. Без спроса ничего не ставится. Архив проверяется по `SHA256SUMS` из релиза. Если sai лежит в папке, куда нужны права администратора, запустите `sudo sai upgrade`.

## Настройка

Файл `~/.config/sai/config.toml` (на Windows `%APPDATA%\sai\config.toml`):

```toml
ssh_key = "~/.ssh/id_ed25519"
ip = "1.2.3.4"
```

### Своя защита сервера

Если вы хотите сами настраивать ssh, порты и фаервол (например, на VPS уже что-то работает), используйте `sai setup --minimal`. Он ставит только то, без чего sai не работает: Docker, пользователя `sai` с входом по ключу, изолированную сеть контейнеров и базовый образ. ssh, фаервол и fail2ban он не трогает. Укажите в конфиге порт ssh вашей VPS:

```toml
ssh_key = "~/.ssh/id_ed25519"
ip = "1.2.3.4"
port = 22
```

Если потом смените порт ssh, поменяйте и `port` в конфиге. Пароль при `setup` можно оставить пустым, тогда sai войдёт по ключу из конфига.

Общие правила для агентов можно написать в `~/.config/sai/AGENTS.md` рядом с конфигом. Их получают все агенты во всех проектах.

### Что агенту можно

По умолчанию агентам запрещено удалять файлы (`rm`, `rmdir`, `unlink`, `shred`, `git clean`), коммитить, пушить и менять ветки и историю через git. Это можно поменять в конфиге:

```toml
[agents]
allow = ["npm test", "git commit"]   # выполнять без вопросов, снимает встроенный запрет на эту команду
deny = ["curl", "wget"]              # запретить всегда
restrictions = false                 # снять все встроенные запреты
```

Команда задаётся первыми словами: `"git"` разрешает всё, что начинается с `git`, `"git commit"` — только коммиты. Один список работает и для Claude, и для Codex. Если ничего не указать, действуют встроенные запреты. Без них агент может удалить файлы проекта, тогда вернуть их можно только из снапшота. `sai doctor` покажет, какие запреты сняты. Изменения применяются при следующем `sai chat`.

Дальше:

```bash
sai setup
cd ~/code/shop
sai chat
```

Чтобы агент видел сразу несколько папок, например фронтенд и бэкенд, добавьте их в один проект:

```bash
sai attach shop ~/code/frontend
sai attach shop ~/code/backend
sai chat shop
```

## История git

Если подключаемая папка — git-репозиторий или внутри неё лежат репозитории, sai спросит, дать ли агенту их историю. Репозитории ищутся на глубину до 4 папок, историю получают первые 20, новые подхватываются сами при следующем `sai chat`. Агент сможет смотреть `git log`, `git diff`, ветки и проверять, есть ли правка в нужной ветке. Только чтение: изменения в `.git` на VPS к вам не попадают, а команды, которые меняют ветки, историю или файлы (`commit`, `push`, `checkout`, `switch`, `restore`, `reset`, `stash`, `merge`, `rebase`, `cherry-pick`, `revert`, `pull`, `am`, `worktree`, `clean`), агентам запрещены. Посмотреть файл из другой ветки агент может через `git show ветка:путь`, а перенести фикс — правкой файлов. История обновляется сама, когда вы коммитите или переключаете ветки у себя. На VPS не уходят `.git/config` (там бывают токены), хуки и журнал ссылок. Но если в истории когда-то был закоммичен секрет, агент сможет его увидеть. Включить историю для уже подключённой папки: снова `sai attach <проект> <папка>`.

## Внутри агента

- Колесо мыши прокручивает разговор назад, выделение мышью копирует текст. Если в вашем терминале копирование не срабатывает, выделяйте с зажатым Shift (Windows, Linux) или Option (Mac).
- `Ctrl+B`, затем `D` — вернуться в sai, агент продолжит работать. `/exit` — остановить агента.
- В меню sai `?` показывает все клавиши.

## Что sai проверяет за агентом

Синк работает, только пока открыт sai (меню, чат, `shell` или `vps`). Когда закрывается последний sai, он досылает изменения и ставит синк на паузу, при следующем запуске синк продолжается сам. Агент на VPS при этом продолжает работать, его изменения приедут к вам, когда вы снова откроете sai. Так файлы с VPS не попадают на ваш компьютер, пока вас нет рядом.

Если вы и агент поменяли один файл одновременно, побеждает версия агента: синк не останавливается на конфликте. Вашу версию можно вернуть только если она успела попасть в снапшот.

В проекте может быть сколько угодно чатов, но работает всегда один агент в одном чате, как `RwLock` в Rust: читать (список чатов, переписку, снапшоты, `sai shell`) можно сколько угодно параллельно, а менять — только одному. Пока агент выполняет задачу или ждёт ответа, sai не переключит чат, не удалит его, не восстановит снапшот, не отключит папку и не удалит проект. Если sai открыт в нескольких терминалах, они не мешают друг другу: второй ждёт, пока первый закончит готовить проект.

У каждого проекта своя история чатов агента: агент в одном проекте не видит переписку из другого. Общий у всех проектов только вход в аккаунт Claude или Codex.

Некоторые файлы запускают код у вас на компьютере: git-хуки (`.husky/`, `.githooks/`), `.envrc`, `package.json`, `Makefile`, `build.rs`, `.vscode/`, `.github/workflows/`, `docker-compose.yml` и подобные. Если они изменились (агентом или вами), sai напомнит после выхода из чата, отметит проект в меню знаком `!` и покажет список при открытии проекта. Посмотрите изменения перед тем, как что-то запускать или коммитить. Изменения `.saiignore` и `.gitignore` тоже попадают в этот список.

## Windows

- Запускайте sai во вкладке **PowerShell** в Windows Terminal. В MSYS2 и Git Bash известны баги с Ctrl+C и мусором в терминале при работе с Windows-программами, а окно mintty вообще не подходит.
- sai использует встроенный в Windows OpenSSH. Если `sai doctor` пишет, что версия старая, поставьте свежую с [Win32-OpenSSH](https://github.com/PowerShell/Win32-OpenSSH/releases), sai подхватит её сам.
- Если после обрыва связи терминал начал печатать что-то вроде `35;77;3M`, закройте вкладку и откройте новую.

## Команды

| Команда | Что делает |
|---|---|
| `sai setup [--minimal]` | Настроить VPS, `--minimal` не трогает ssh, фаервол и fail2ban |
| `sai attach <проект> [папка] [--agent claude\|codex] [--as имя]` | Добавить папку к проекту, новый проект создаётся сам. Агент по умолчанию Claude |
| `sai detach <проект> [папка или её имя]` | Убрать папку из проекта. Локальные файлы не трогаются, копия на VPS удаляется, но остаётся в снапшотах |
| `sai files [проект] [папка]` | Выбрать, что из папки заливать на VPS. Снятое остаётся у вас, с VPS удаляется, но остаётся в снапшотах |
| `sai chat [проект] [--new] [--open N]` | Открыть агента. Если чат один, sai открывает его, если несколько — показывает список. После `/exit` чат продолжается с того же места. `--new` (в меню `new chat`) начинает ещё один чат, пока агент работает над задачей, это недоступно. В ещё не привязанной папке сам создаёт проект с её именем |
| `sai chats [проект] [--show N] [--rm N]` | Список чатов проекта. `--show` показывает переписку только для чтения (в меню `v` в списке чатов), `--rm` удаляет чат (в меню `rm chat`). Чат, в котором агент сейчас работает, удалить нельзя |
| `sai change <claude\|codex> [проект]` | Сменить агента проекта |
| `sai shell [проект]` | Открыть bash внутри контейнера |
| `sai vps` | Открыть bash на самой VPS под пользователем `sai` (без sudo): проекты, снапшоты, `docker ps`. `exit` или `/exit` возвращает обратно в sai. Из любого терминала то же самое: `ssh sai` |
| `sai list` | Проекты и их папки |
| `sai status` | Загрузка VPS и агентов |
| `sai doctor` | Проверить, что всё работает, и подсказать, как починить |
| `sai logs` | Сохранить отчёт с логами в текущую папку, чтобы отправить его при проблеме |
| `sai rename <проект> <новое имя>` | Переименовать проект |
| `sai stop [проект]` | Остановить проект |
| `sai rm <проект> [--purge]` | Удалить проект, `--purge` удаляет и файлы на VPS. Локальные папки не трогаются |
| `sai resolve [проект]` | Залить твои локальные версии файлов поверх версий на VPS |
| `sai snapshots [проект]` | Список снапшотов |
| `sai review [проект]` | Показать изменённые файлы, которые могут запускать код на вашем компьютере, и отметить их проверенными |
| `sai restore <снапшот> [путь] [--project проект]` | Восстановить проект, папку или файл из снапшота. Путь начинается с имени папки: `frontend/src/app.ts` |
| `sai update` | Пересобрать образы со свежими версиями |
| `sai upgrade` | Обновить сам sai до последней версии |
| `sai reset [--all]` | Удалить с VPS всё, что создал sai: контейнеры, логины агентов, файлы проектов, снапшоты и образы агентов. `--all` удаляет и базовый образ |
| `sai completions <shell>` | Вывести скрипт автодополнения. Для zsh, bash и fish sai ставит его сам при первом запуске |

Просто `sai` без аргументов открывает интерактивное меню со списком проектов и всеми действиями. Если проект не указан, sai берёт тот, к которому привязана текущая папка. Папка по умолчанию — текущая, её имя внутри проекта — имя папки, другое можно задать через `--as`. Одна папка может быть только в одном проекте. Проект привязан к одному агенту: к тому, с которым его создали. Сменить агента можно через `sai change`.

В меню sai папки проекта выбираются в дереве папок вашего компьютера: пункт `folders` в меню проекта, а для нового проекта `attach`. Галочка на папке подключает её, снятая галочка отключает (локальные файлы остаются, копия на VPS удаляется и остаётся в снапшотах). Стрелкой `→` папку можно раскрыть и снять галочки с того, что агенту не нужно, например с больших данных: это не уйдёт на VPS. Рядом видны размеры, `/` позволяет вписать путь. Всё, что в `.gitignore` (а вне git-репозиториев папки вроде `build`, `dist`, `.idea`), при подключении сразу снято и подписано, при необходимости галочку можно вернуть. Всё применяется по Enter одним действием.

В командной строке то же самое делают `sai attach`, `sai detach` и `sai files`. Сборки, виртуальные окружения, `node_modules` и секреты не заливаются никогда, в списках их нет.

Для продвинутых есть файл `.saiignore` с шаблонами, как у `.gitignore`, например `*.log`. Его можно положить в корень папки или в любую подпапку.
