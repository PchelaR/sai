# sai

Утилита для запуска ИИ-агентов (Claude Code, Codex и Kimi Code) на VPS. Агент работает в изолированном Docker-контейнере, а папка проекта синхронизируется между локальным пк и VPS.

## Как это работает

- `sai setup` один раз настраивает чистую Ubuntu-VPS: создаёт пользователя `sai`, оставляет вход только по ключу на порту 28522, включает фаервол и fail2ban, ставит Docker и собирает базовый образ с Python и Rust. Образ самого агента собирается за пару минут при первом `chat` с ним.
- `sai chat` синхронизирует папку с VPS через mutagen и открывает агента. Агент видит только папку проекта и интернет, до самой VPS и других проектов доступа нет.
- Агент продолжает работать, даже если закрыть терминал. Повторный `sai chat` возвращает в ту же сессию.
- Секреты (`.env`, ключи, сертификаты и т.п.) и `.git` на VPS не попадают.
- Перед каждым `chat` и каждые 15 минут на VPS делается снапшот проекта, из него можно восстановить файлы.

## Требования

- OpenSSH, `curl` и `tar` (на macOS, Linux и Windows 10+ они уже есть). Mutagen для синка sai скачивает и ставит сам
- ssh-ключ, например `~/.ssh/id_ed25519`
- чистая VPS с Ubuntu 22.04 или новее и пароль от пользователя


## Установка

Скачайте архив под свою систему во вкладке Releases, распакуйте и положите `sai` в `/usr/local/bin`.

## Настройка

Файл `~/.config/sai/config.toml` (на Windows `%APPDATA%\sai\config.toml`):

```toml
ssh_key = "~/.ssh/id_ed25519"
ip = "1.2.3.4"
```

Общие правила для агентов можно написать в `~/.config/sai/AGENTS.md` рядом с конфигом. Их получают все агенты во всех проектах.

Дальше:

```bash
sai setup
cd ~/my_project
sai chat
```

## Команды

| Команда | Что делает |
|---|---|
| `sai setup` | Настроить VPS |
| `sai chat [папка] [--agent claude\|codex\|kimi]` | Открыть агента для папки, по умолчанию Claude |
| `sai change <claude\|codex\|kimi> [папка]` | Сменить агента проекта |
| `sai attach [папка]` | Подключить папку и запустить контейнер, не открывая агента |
| `sai shell [папка]` | Открыть bash внутри контейнера |
| `sai list` | Список проектов |
| `sai status` | Загрузка VPS и агентов |
| `sai doctor` | Проверить, что всё работает, и подсказать, как починить |
| `sai stop <имя>` | Остановить проект |
| `sai rm <имя> [--purge]` | Удалить проект, `--purge` удаляет и файлы на VPS |
| `sai resolve [папка]` | Решить конфликты синка в пользу локальных файлов |
| `sai snapshots [папка]` | Список снапшотов |
| `sai restore <снапшот> [путь] [--dir папка]` | Восстановить проект, папку или файл из снапшота |
| `sai update` | Пересобрать образы со свежими версиями |
| `sai reset [--all]` | Удалить с VPS всё, что создал sai: контейнеры, логины агентов, файлы проектов, снапшоты и образы агентов. `--all` удаляет и базовый образ |
| `sai completions <shell>` | Автодополнение для терминала |

Просто `sai` без аргументов открывает интерактивное меню со списком проектов и всеми действиями. Папка по умолчанию — текущая. Имя проекта — имя папки. Проект привязан к одному агенту: к тому, с которым его открыли первым. Сменить агента можно через `sai change`.

Свои исключения для синка можно добавить в файл `.saiignore` в корне проекта.
